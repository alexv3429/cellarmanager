# CellarManager v0.3.0

v0.3.0 is CellarManager's personal-production baseline. It expands the
local-first v0.2 inventory foundation into the application used to browse,
maintain, import, and verify a real cellar day to day.

## Highlights

- URL-backed Inventory, Catalog, Activity, Import, and Cellar setup workspaces
  with refresh and browser Back/Forward support
- mobile-first inventory search and cellar/location filtering
- everyday ADD, MOVE, and REMOVE workflows plus detailed wine views
- editable wine identity, metadata, vintage, and bottle format
- configurable cellar/location ordering, capacity, occupancy, and archiving
- visible recent inventory activity and local/remote synchronization state
- installable PWA behavior, narrow-viewport navigation, and accessibility polish

## CSV import

The permanent product importer now provides the complete guarded flow:

`upload -> map -> clean -> preview -> resolve -> preview -> commit`

It supports comma, semicolon, and tab-delimited UTF-8 files; maps arbitrary
headers; preserves source-row provenance; cleans and normalizes values; matches
existing wines; detects ambiguity; reconciles cellar, location, and quantity;
and previews the exact outcome before any bottle data is written.

Real-world import support includes all-row values for omitted columns, blank
Cuvée fallbacks, `NM`/`N.M.` to `NV` normalization, explicit blocking feedback,
and creation of an initial cellar plus location for a new physical stock. The
final authoritative write is transactional and idempotent.

## Data and safety

- PostgreSQL holdings remain authoritative.
- ADD, MOVE, and REMOVE retain their local-first, offline-capable behavior.
- Household ownership and row-level security remain the isolation boundary.
- CSV preparation is read-only until the explicit final commit.
- The accepted production household was not reset or re-imported for release.
- The retired v0.1 runtime and one-off migration tooling remain available only
  through historical Git tags.

Deployments upgrading from v0.2 must apply the committed Supabase migrations in
order before serving the v0.3 web build. No destructive release migration is
required.

## Acceptance

The release passed repository policy checks, web lint and production PWA build,
193 web tests across 33 files, 211 pgTAP database tests across 12 files, the
production-dependency audit at the high-severity threshold, and clean Git diff
validation.

The final personal-production smoke pass covered authenticated refresh,
synchronization readiness, inventory totals and filters, wine details,
URL-backed navigation, Activity, Catalog, cellar setup, and a read-only CSV
preview. Additional real-world import validation covered omitted formats, blank
Cuvée values, non-vintage normalization, and first-cellar creation.

See [`../v03-personal-production-acceptance.md`](../v03-personal-production-acceptance.md)
for the complete acceptance record and [`../v03-roadmap.md`](../v03-roadmap.md)
for the completed Milestone 3 delivery sequence.

## Deferred scope

CSV export, duplicate/merge tooling, shared-household workflows,
capture/enrichment, internationalization, advanced graphical cellar layouts,
and purchase/value history remain post-v0.3 work. Bulk CSV import may require
an online connection; everyday inventory operations continue to work offline.
