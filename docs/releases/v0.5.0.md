# CellarManager v0.5.0

v0.5.0 adds shared-household collaboration to the local-first cellar and wine
library introduced in v0.4. PostgreSQL remains authoritative when users or
devices make concurrent changes.

## Shared households

- A clear Owner/Member permission boundary is enforced server-side. Members can
  browse; owners retain inventory, import, and cellar-setup management.
- Owners can invite collaborators, manage roles and access, transfer ownership,
  or leave safely. Users can switch between households without mixing their
  data.
- Account settings support each user's display name and verified password
  changes. Device management provides audited rename and revocation workflows.
- Concurrent inventory operations remain idempotent. Rejected and blocked
  offline operations explain the conflict and provide explicit recovery rather
  than silently changing stock.
- Cross-role security and invitation-race tests protect household isolation
  and authorization boundaries.

## Spreadsheet import

The owner-only workbook importer is more resilient to third-party cellar files:
rows can be corrected, replaced in bulk, or explicitly excluded; generic
column splitting and missing-value defaults help normalize source formats;
and grouped storage review can create or reuse cellars and locations before
the final import. Zero-quantity catalog rows remain distinct from physical
stock and create no storage or inventory activity. All destination and import
changes remain explicit and reviewable.

## Upgrade and release notes

Apply the committed Supabase migrations in order before deploying the v0.5 web
build and Worker. The final v0.5.13 migration adjusts catalog-only import
functions and receipt validation; it does not modify existing cellar or bottle
records. No cellar reset or re-import is required. The migration has already
been applied and verified in the linked production database for this release
candidate.

The deployed Worker must report `v0.5.0` and pass the read-only production
readiness check before tagging. See
[`../v05-acceptance.md`](../v05-acceptance.md) for evidence, remaining
post-deployment checks, and the explicit boundary of the offline-device
acceptance.

The next milestone is v0.6: per-user English/French localization first,
followed by capture-assisted wine entry. See the
[`product roadmap`](../product-roadmap.md) for the canonical sequence.
