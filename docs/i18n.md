# Internationalization

The app ships with English and French. Adding a third language touches only
JSON files - no code changes.

## Backend

1. Copy `backend/app/i18n/en.json` to `backend/app/i18n/xx.json` (use the
   two-letter code for your language) and translate the values.
2. That's it - `backend/app/i18n/loader.py` discovers every `*.json` file in
   that directory automatically (`available_locales()`), and
   `GET /i18n/{locale}` will serve it. Unknown locales fall back to English;
   missing individual keys in `xx.json` also fall back to the English value
   for that key, so a partial translation never shows a broken UI.

## Frontend

1. Copy `frontend/i18n/en.json` to `frontend/i18n/xx.json` and translate.
2. Add `"xx"` to `SUPPORTED_LOCALES` in `frontend/js/i18n.js`.
3. Add an option to the language `<select>` if you want it in the nav
   switcher (`frontend/js/app.js`, `renderNav()`) - or leave it
   auto-detected from the browser's language only.

Both dictionaries are flat `"key": "value"` maps; a value can contain
`{placeholders}` filled in via `t("key", {placeholder: value})` (backend:
`app/i18n/loader.py: translate()`; frontend: `js/i18n.js: t()`).

## What is *not* translated

Proper nouns from the wine catalog itself - producer, cuvée, appellation,
area/region - are never translated (there is no "French version" of
"Domaine Jean-Marc Burgaud"). Only UI chrome and a handful of controlled
vocabularies are: color (`red/white/rosé/sparkling/orange/fortified/other`)
and bottle state (`in_cellar/gifted/broken/sold/lost/drunk`), both on
screen and in CSV export headers/values (see `docs/data-model.md`).

## CSV import/export language handling

Import recognizes English *or* French column headers in the same file
(matched case- and accent-insensitively - see `app/services/csv_io.py:
HEADER_ALIASES`). Export takes an explicit `language` parameter and
translates headers and enum values (color/state) accordingly; the default
delimiter is also locale-aware (`;` for French, `,` otherwise, matching
Excel's regional conventions), though it can be overridden.

## Keeping the two language files in sync

There's no automatic check built into the app itself, but the project's own
build process included one: a small script cross-referenced every literal
`t("...")` call in the frontend against `en.json`'s keys, and diffed
`en.json`'s and `fr.json`'s key sets against each other, catching a couple
of real typos before they shipped. If you add UI strings, it's worth
re-running the same idea (`grep -o 't("[a-zA-Z0-9_.]*"' -r frontend/js`
against the keys in both JSON files) before committing.
